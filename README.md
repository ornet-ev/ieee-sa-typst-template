# Typst Standard Crafting Template

A Typst template providing a scaffold to develop SDC standards capturing requirements and collecting implementation conformity statements. 

Typst can produce a PDF preview and a custom-element HTML export, which can be post-processed into Word. Requires Typst `0.15.1` or newer.

> [!IMPORTANT]
> **This is an unofficial template.** It is an independent, community-maintained project and is **not** created, endorsed, approved, or affiliated with the IEEE, the IEEE Standards Association (IEEE SA), or any of their committees. Documents produced with it are **not** official IEEE standards or IEEE drafts, and using it does not grant any IEEE approval, project authorization (PAR), or designation.

Always use the official IEEE SA authoring tools, templates, and the *IEEE Standards Style Manual* for any document submitted to IEEE. The default "Word usage" text is adapted from the IEEE Standards Style Manual and can be replaced via the `word-usage` parameter.

## Including the library

The package is named `ieee-sa-compatible-standard` (see `typst.toml`). It is not published on Typst Universe, so use one of:

### Relative import

Clone (or copy) this repository next to your document (preferred until there is a better way to provide custom remote repositories):

```typ
#import "path/to/ieee-sa-compatible-standard/lib.typ": *
```

It is recommended to clone this repository as a Git submodule into your project.
Use Git tags to refer to the version you like to use:

- `x.y.z.` to include version `x.y.z`
- `latest` to include the latest version - be cautious as this may yield incompatible changes when updating the submodule.

### Local package

Copy the repository to `{data-dir}/typst/packages/my-repo/ieee-sa-compatible-standard/x.y.z/` (`{data-dir}` is `%APPDATA%` on Windows, `~/.local/share` on Linux, `~/Library/Application Support` on macOS), then:

```typ
#import "@my-repo/ieee-sa-compatible-standard:0.1.0": *
```

Note that depending on the name of the directory below `packages`, the path after `@` changes accordingly.

## Using the library

Apply `ieee-sa-compatible-standard` with a `show` rule. The metadata, abstract, keywords, introduction, normative references, scope, and abbreviations are required.

```typ
#import "@local/ieee-sa-compatible-standard:0.1.0": *

#show: ieee-sa-compatible-standard.with(
  metadata: document-metadata(
    designation: "11073-10207",
    draft-number: "05",
    par-title: "Example Standard",
    committee-name: "Example Committee",
    society-name: "Example Society",
    working-group-name: "Example Working Group",
    standard-type: standard-type.standard,
    document-type: document-type.revision,
  ),
  abstract: [An abstract.],
  keywords: ("keyword one", "keyword two"),
  introduction: [An introduction.],
  scope: [The scope of this standard.],
  abbreviations: ((short: "ICS", long: "Implementation Conformance Statement"),),
  normative-references: (
    normative-reference(
      reference: "ref:ieee-11073",
      label: "IEEE Std 11073-10207",
      text: [Full bibliographic entry.],
    ),
  ),
  definitions: (
    definition(term: "device", description: [A thing that does stuff.]),
  ),
  notational-conventions: [...],
  informative-bibliography: (),
  normative-annexes: (annex(title: "Details", reference: "annex:details")[Annex content],),
  informative-annexes: (),
  ics-annex: annex(title: "ICS", reference: "annex:ics")[
    #render-ics-table(feature: "Server")
  ],
)

= Requirements

#requirement(
  category: requirement-category.technical,
  number: 1,
  ics-assignment: "Server",
  level: requirement-level.shall,
)[The server must do X. #notes(note[An explanatory note.])]
```

The optional `word-usage` parameter replaces the default "Word usage" clause (shall/should/may/can), e.g. `word-usage: [Your own wording.]`.

Everything after the `show` rule is the main content. The numbered clauses (Overview, Normative references, Definitions) are generated by the template.

### Building

```sh
# PDF preview
typst compile main.typ

# HTML export
typst compile --features html --format html main.typ

# PDF without the DRAFT watermark
typst compile --input draft=false main.typ
```

### Exported building blocks

| Symbol | Purpose |
| --- | --- |
| `ieee-sa-compatible-standard`, `document-metadata`, `standard-type`, `document-type` | Document template and its metadata |
| `requirement`, `requirement-category`, `requirement-level` | Numbered, referenceable requirements (numbers must be unique) |
| `render-ics-table` | ICS table for one role, built from the requirements' `ics-assignment` |
| `definition`, `normative-reference`, `bibliography` | Referenceable entries; cite them with `@reference` |
| `notes`, `note` | Numbered NOTE groups |
| `annex` | Normative/informative annex (no level-1 headings in the body) |
| `horizontal` | Landscape page for wide tables |
| `todo` | Inline TODO marker |
